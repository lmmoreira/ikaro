Discovery Prototype — Tenant Billing

Mockups for the model in tenant-billing.md, use cases in tenant-billing_USECASES.md, API in tenant-billing_API.md and module spec in tenant-billing_MODULE.md. Fictional tenants (Lavacar BeloAuto and Ikaro for BR, Sunrise Auto Spa for US) and one fictional visitor (Maria Souza): Lavacar BeloAuto (BR, pays Ikaro) and Ikaro (the platform's own tenant and marketing site). Handoff details per screen: dev-notes.md.

Illustrative only. This is not a journeys/ prototype: prices, dates, tier names and the Ikaro URL are invented. Tokens, the dashboard shell and the hotsite pages are the real ones from journeys/shared/. Tags: green = reuses an existing component, red = new component (GAP).

O que este protótipo valida

  • O gerente entende, na página de cobrança, o que paga, até quando e como pagar em um clique?
  • Ficar suspenso sem poder usar nada além da cobrança é claro, e o caminho para voltar (pagar 1 mês) é óbvio?
  • O selo "Empresa inativa" e o bloqueio do detalhe de agendamentos abertos fazem sentido para o cliente final?
  • O recurso bloqueado (upsell) deixa claro que as configurações foram preservadas?
  • A página /ikaro-trial mostra preços e recursos o suficiente para decidir antes de entrar com o Google?
  • A confirmação de cancelamento deixa claro "sem reembolso" e a política de limpeza dos dados?
