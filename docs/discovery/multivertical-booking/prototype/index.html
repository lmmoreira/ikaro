Discovery Prototype — Multi-Vertical Scheduling

Directional mockups for the scheduling model explored in multivertical-booking.md and multivertical-booking_USECASES.md. One fictional tenant, Vitta Studio, runs all three example verticals at once — Hair Styling (per-staff, customer-chosen appointment), Pilates (class, capacity 4), and CrossFit (class, capacity 20) — so a single resource (Camila Duarte) can show up as both a 1:1 hair stylist and a group Pilates instructor, the concrete instance of the "capacity as Service × Resource" finding (discovery §2, model #13).

Illustrative only. This is not a plan/journey/ prototype — no /docs-audit, no mandatory unhappy-path variants, no dev-notes handoff spec at that depth. One representative screen per concept, reusing the real --ba-* tokens and dashboard shell so it reads authentically, but built to validate the product direction. Newer screens below add the decision-complete reservation lifecycle; promotion to a formal plan/journey/ handoff still requires its own audit and journey workflow.

Jornada pública canônica

Hotsite → serviço → modelo de agendamento → dados/confirmação. “O que você gostaria de agendar?” é o ponto de entrada padrão para um negócio com mais de um serviço. A partir dele: atendimento individual vai para profissional (quando a escolha é configurada), turma vai para agenda de turmas filtrada pelo serviço, e sala/locação vai para data, horário e duração. As telas abaixo que começam em profissional, agenda ou horário são etapas internas ou deep links de demonstração, não portas concorrentes.
