Discovery Prototype — Hotsite Chatbot

Directional mockups for the chatbot module explored in CHATBOT.md. One fictional tenant, BeloAuto — reusing the same tenant, branding tokens, and public-hotsite base already established in the manager hotsite prototype — shows the widget in both layout variants and all three states from CHATBOT.md §7 ("Widget States & Failure UX"), plus the admin-facing module config screen.

Illustrative only. This is not a plan/journey/ prototype — no /docs-audit, no mandatory unhappy-path variants, no dev-notes handoff spec at that depth. One representative screen per concept, reusing the real --ba-* tokens and shared component classes so it reads authentically, built to answer "what direction are we heading," not to be implementation-ready.

Public hotsite — widget states (§7)

  • Conversa em andamento bubble · active
  • Limite atingido — conversa interrompida bubble · interrupted

Caps are deliberately absent from both config screens. Fixed platform defaults for MVP, not tenant-editable anywhere in the admin UI — a non-technical tenant admin has no way to judge the cost consequence of raising a number like maxConversationsPerDay (CHATBOT.md §5). 07-tenant-settings.html shows this next to the existing Localização section's readonly pattern for contrast — caps aren't quite that either; they're just not in the admin UI at all yet.
